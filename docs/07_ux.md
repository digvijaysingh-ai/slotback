# 07 · UX

**What this covers:** the eight web surfaces of the Slotback demo (one landing page plus seven app pages), the decisions from the design review, and links to an ASCII wireframe for each page.
**Visual system:** `DESIGN.md` is the single reference for tokens, type, spacing, components and accessibility. This document summarises the decisions; it doesn't repeat the token tables.
**Decision source:** "Design Review Decisions" in `docs/designs/slotback-full-build.md`.

---

## 1. Design decisions (summary)

| Decision | What it means on screen |
|---|---|
| **Direction B, "Control room"** | Dark, dense and calm. A warm control room for patient work, not a network-operations wallboard |
| **Warm charcoal**, not blue-black | `--bg #151412`. Reads human. Light token set for printed / projected slides |
| **IBM Plex Sans + Plex Mono** | Sans for UI and headings; Mono with tabular figures for every number, ledger line, hash and tag. Inter dropped |
| **One accent (clinic blue)** | Primary actions, links, focus ring, current nav. Every other colour carries a meaning |
| **Status = colour + icon + label** | ✓ filled · ⟳ offering · ✕ unfilled · ◆ care marker. Never colour alone |
| **◆ Care markers** | The same outlined sage marker wherever a safeguard happens: "◆ AI disclosed", "◆ identity verified", "◆ read back", "◆ handed to a human" |
| **Provenance tag on every number (D28)** | Exactly one of `SIMULATED` (filled amber) · `BENCHMARK [S#, year]` · `SYNTHETIC` · `MEASURED` (outlined). Hover shows the source. Values come from `metrics/registry.json` |
| **Numbers are the only hero** | Key metrics in Plex Mono, large, with the tag underneath. Charts only when they answer a question. No cards around metrics |
| **Language (7A)** | Public demo opens in **English** with a prominent ES toggle, remembered per visitor. Calls, transcripts and `readout/es/` are Spanish; transcripts show an English gloss line |
| **Landing page kept (1B)** | One composition, not a grid of boxes: the result, one sentence, one button |
| **Context bar on every page** | "Fictional hospital · synthetic data · simulated results are labelled" |
| **Specialty hidden until verified** | In any UI showing a call, appointment details show "—" until the identity-verified event exists |

## 2. Information architecture

Left rail, current page marked: **Impact · Console · Calls · ROI · Evals · Verify · Try**. The landing page sits outside the rail.

| Page | 1st | 2nd | 3rd | Wireframe |
|---|---|---|---|---|
| Landing | Recovered slots vs SMS-only (SIMULATED) | One-line what & why | "See the live day →" | [landing](wireframes/landing.md) |
| Impact | Recovered-slots number vs SMS-only | Day timeline / replay | Ledger feed + verified status, tamper | [impact](wireframes/impact.md) |
| Console | Live call board by status | Exceptions queue for humans (one-click callback) | Freed-slot feed, cost meter, alerts, kill switch | [console](wireframes/console.md) |
| Call detail | Outcome + flags (privacy, escalation) | Transcript ⇄ tool-call timeline | Ledger events, audio (demo calls only) | [call-detail](wireframes/call-detail.md) |
| ROI | Break-even + € per recovered slot | Sliders, each with a provenance tag | Sensitivity | [roi](wireframes/roi.md) |
| Evals | Gate status PASS / FAIL / ERRORED | Scenario × persona matrix | Leak known-answer result, version comparison | [evals](wireframes/evals.md) |
| Verify | Drop zone (bundle) | Pass/fail per check | What each check proves (plain language) | [verify](wireframes/verify.md) |

**Public vs gated (D17):** every page is readable in public. Every action (kill switch, start campaign, callback, tamper is local-only, Try-it session, verify upload) needs the access code and is logged. Tamper edits an in-memory copy only.

## 4. A first-time visitor's 5 minutes

| Step | User does | Feels | Supported by |
|---|---|---|---|
| 1 | Opens the URL (landing) | Oriented in 5 s | Result + one sentence + one button |
| 2 | "See the live day" | "It already worked" | Impact opens on the **end state** |
| 3 | "Replay the day ▶" | Watching it happen | 60 s replay: freed → offering r1/r2 → filled; counter climbs; ledger lines in sync. Pause, scrub, reduced motion |
| 4 | "Tamper with one event" | "It's provable" | Memory copy edited; verifier turns red at the exact `#seq`; "Restore" |
| 5 | Downloads the bundle → Verify | Checkable without trusting us (tamper-evident) | Verify page passes the bundle and explains each check |
| 6 | Opens a call | "It's careful with patients" | ◆ disclosure → ◆ identity → ◆ read-back in transcript and tool timeline |
| 7 | Evals / ROI | "This person thinks like a deployer" | Gate status first; break-even first |

**Wording note (OV2):** the verifier proves the record wasn't rewritten after the hospital received the signed head. It doesn't prove the fills happened. Billing reconciles against the hospital's own booking record (see `04_business_case.md`). The Verify page says so in plain words.

## 5. Responsive behaviour and accessibility

- **≥1024 px:** three regions: left rail (180–200 px) · workspace · context panel (300–330 px).
- **768–1023 px:** context panel moves below the workspace; rail becomes icons with labels on hover/focus.
- **<768 px:** a deliberate **read-only summary**: headline number, replay as a vertical event list, verify status, "Watch the 3-minute video". No actions on phones.
- WCAG 2.2 AA; body ≥16 px; full keyboard operation (nav, replay play/pause/scrub, tamper/restore, verify upload); visible 2 px focus ring; ARIA landmarks (`nav`, `main`, `complementary`); live counter announced politely at most every 5 s; `prefers-reduced-motion` respected; 44 px touch targets.

## 6. Copy rules (from DESIGN.md)

- Patient-centred labels: "Patients reached", "Slots returned to the waiting list". Never "calls dialled" or "handle time".
- Every number has one provenance tag. No number without a tag, anywhere.
- Utility language for status and actions: "Calling paused", "Start a demo campaign", "Restore".
- Specialty and appointment details show "—" until identity is verified.
